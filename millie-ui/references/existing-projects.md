# Existing Project Design Authority

## Evidence hierarchy

1. Explicit user direction / approved brand system.
2. Existing production tokens and component system.
3. 3–5 strongest current surfaces.
4. Current assets/iconography/fonts.
5. Existing docs/Figma/brand links.
6. Historical/inconsistent styles.

## Classify

### Preserve
Small edit. Match incumbent patterns.

### Extend
New surface. Reuse tokens/components and compose a new solution.

### Repair
System has drift. Identify dominant successful language, unify deviations.

### Redesign
User wants new visual world. Preserve functionality/product truth; replace style coherently.

## DESIGN.md classification

Existing coherent system + no doc:
- document evidence.

Existing docs:
- merge, do not regenerate;
- preserve unique local rules;
- flag code/doc contradictions.

Greenfield:
- Millie auto-selects direction when user gives none;
- write design language after selection for long-lived projects.

## Visual DNA extraction

Record:
- type roles;
- neutral temperature;
- accent behavior;
- spacing rhythm;
- grid;
- radius/shape;
- border/elevation;
- icons;
- imagery;
- motion;
- navigation;
- component state treatment.

Do not let one poorly styled legacy page define the system if several newer polished pages disagree.

## Refinement vs redesign

Refinement preserves identity.
Redesign replaces identity but preserves product function/constraints.

Do not blend a discarded old style with a new direction out of fear.
