# <img src="./assets/icons/spark.svg" width="28" align="center" alt="" /> What is Millie UI?

**Millie UI/UX** is a portable Agent Skill designed to make AI-generated interfaces feel like deliberately designed products instead of reusable AI templates.

Millie combines the responsibilities of a:

```text
Product designer
UX architect
Visual art director
Design-system designer
Interaction designer
Motion designer
Frontend engineer
Accessibility reviewer
Responsive/adaptive designer
Native-app UI designer
Creative developer
3D/WebGL engineer
Visual QA reviewer
```

Millie is not a component library.

Millie is not a fixed theme.

Millie is not a collection of random animations.

Millie is a **decision system** for choosing the right visual, interaction, implementation, and verification strategy for the product in front of the agent.

# <img src="./assets/icons/brain.svg" width="28" align="center" alt="" /> The Main Difference

Without a design skill, an AI agent can easily fall into:

```text

      +

      +

      +
```

```text
   ↓

   ↓
PLATFORM / DEVICE
   ↓

   ↓
```

The result should look and behave as if the decisions belong to **this product**, not to the AI model that generated it.

# <img src="./assets/icons/radar.svg" width="28" align="center" alt="" /> Research-First Design

For significant, creative, trend-sensitive, or brand-critical interfaces, Millie can research before designing.

It can inspect:

```text
category leaders
real competitor products
current design systems
professional showcases
open-source implementations
platform guidance
motion references
creative-development examples
3D experiences
community criticism
component ecosystems
```

Millie then extracts **principles**, not copied layouts.

The research process is designed around:

```text
RESEARCH
   ↓
SELECT USEFUL REFERENCES
   ↓
IDENTIFY WHAT EACH CONTRIBUTES
   ↓
IDENTIFY WHAT MUST NOT BE COPIED
   ↓
LOCK DIRECTION
   ↓
BUILD
```

For major creative work, Millie can use:

```text
templates/RESEARCH_LOCK.md
```

to prevent reference drift.

> [!IMPORTANT]
> Research is proportional. A small button adjustment should not trigger a full design-industry research project.

# <img src="./assets/icons/apps.svg" width="28" align="center" alt="" /> Surface Intelligence

Millie does not style everything according to the company's industry.

It classifies the **current surface**.

| Mode | Typical Surface | Primary Goal |
|---|---|---|
| **PERSUADE** | Landing, pricing, campaign, product marketing | Understand + trust + convert |
| **OPERATE** | SaaS, dashboard, editor, admin, developer tool | Complete repeated work efficiently |
| **READ** | Docs, publication, changelog, article | Find and consume information |
| **TRANSACT** | Checkout, booking, banking, application | Complete a high-consequence flow correctly |
| **EXPLORE** | Portfolio, gallery, entertainment, campaign experience | Discover, feel, explore |
| **NATIVE** | Android, iOS, desktop, tablet, wearable | Behave naturally on the platform |

For example:

```text
Cybersecurity company landing page
        ↓
PERSUADE

Cybersecurity analyst console
        ↓
OPERATE

Bank transfer flow
        ↓
TRANSACT

Fashion portfolio
        ↓
EXPLORE
```

This prevents the same brand from receiving the same interface logic everywhere.

# <img src="./assets/icons/wand.svg" width="28" align="center" alt="" /> Auto Premium Mode

If the user provides a design direction, Millie follows it.

If the user gives **no useful visual direction**, Millie does not default to its own favorite template.

It automatically evaluates:

```text
product category
audience
primary task
trust requirement
error cost
content type
content density
platform
screen/window behavior
brand evidence
existing design authority
performance budget
accessibility constraints
```

Then it internally creates multiple genuinely different candidates.

Example:

```text
Candidate A
Swiss editorial
Warm mineral neutrals
Asymmetric project grid
Grotesk + restrained serif
Image-mask motion

Candidate B
Spatial contemporary
Cool neutral field
Layered depth
Geometric type
Interactive 3D model

Candidate C
Luxury minimal
Near-white canvas
Photography-first composition
High-contrast display type
Restrained cinematic transition
```

Millie scores the candidates and chooses the strongest fit.

It does **not** expose internal candidate generation unless the user asks to compare options.

# <img src="./assets/icons/layout.svg" width="28" align="center" alt="" /> Layout & Proportion

Millie does not start with:

```text
1200px container
3 columns
4 stat cards
```

It reasons from available space and useful component size.

Conceptually:

```text
candidate columns
=
floor(
  usable width
  /
  minimum useful component width
)
```

Then Millie reduces that number according to comprehension and comparison quality.

It also classifies visual density.

```text
1–3   Gallery / relaxed
4–7   General product
8–10  Cockpit / professional data
```

A dense SOC dashboard and a fashion portfolio should not share the same spacing philosophy.

# <img src="./assets/icons/motion.svg" width="28" align="center" alt="" /> Motion Director

Millie v2 contains **43 structured motion and interaction patterns**.

Before animating something, it asks:

```text
VERB
What happened?

REVERSIBLE
Does the opposite action exist?

INITIATOR
What caused it?

SPATIAL SOURCE
Where did the new state originate?

AFFORDANCE LOAD
How often is this interaction used?
```

This makes motion semantic.

Example:

```text
Open
→ reveal from source

Close
→ reverse toward source

Delete
→ move away / disappear

Select
→ settle into active state

Expand
→ reveal from anchor
```

For a long-lived project, Millie can create or update:

```text
DESIGN.md
```

using:

```text
templates/DESIGN.md
```

Existing repositories are evidence-driven:

```text
actual tokens
actual components
actual polished screens
actual typography
actual motion
actual navigation
```

Millie does not invent a design system just because the documentation is missing.

# <img src="./assets/icons/code.svg" width="28" align="center" alt="" /> Existing Projects

Millie classifies existing-project work into:

### PRESERVE

Small change. Follow the established design language.

### EXTEND

Add a new surface using the existing system.

### REPAIR

The product has visual drift. Preserve the strongest recurring design DNA and unify inconsistencies.

### REDESIGN

The user explicitly wants a new visual world.

This prevents:

```text
"Add one settings button."
        ↓
AI redesigns the whole app
```

# <img src="./assets/icons/shield-alert.svg" width="28" align="center" alt="" /> Anti-AI-Slop Engine

Millie checks for generic combinations, including newer AI design defaults.

Examples:

```text
purple/blue gradient + centered hero
cream + fancy serif + terracotta for every luxury brand
near-black + acid green for every technical product
broadsheet editorial for every creative site
glass + glow + giant rounded cards
four stat cards + fake chart
cybersecurity + Matrix rain
fake terminal
icon tile above every heading
same font across unrelated projects
same composition across unrelated projects
every section fade-up
random 3D object
```

Individual techniques are not universally banned.

The problem is **unearned repetition**.

Millie's litmus test:

> If the logo were replaced with a competitor's logo, would the interface still make equal sense?

If yes, the design probably needs stronger product-specific decisions.

```text
focus not obscured

zoom

target size
```

```text

>= 3 : 1
```

# <img src="./assets/icons/shield-alert.svg" width="28" align="center" alt="" /> Hard Gates

Millie does not allow aesthetics to compensate for fundamental failures.

Applicable completion gates include:

- [ ] Primary task works
- [ ] Interface is understandable
- [ ] Keyboard/touch/pointer behavior is appropriate
- [ ] Important state is not communicated by color alone
- [ ] Important state is not communicated by hover alone
- [ ] Critical content remains reachable
- [ ] Reduced-motion behavior exists when motion is used
- [ ] Loading/empty/error states exist when applicable
- [ ] No fabricated product claims or fake metrics
- [ ] Existing product truth is preserved
- [ ] Responsive/adaptive behavior is intentional
- [ ] Accessibility constraints are respected
- [ ] 3D has a fallback when needed
- [ ] Expensive effects have a performance justification
- [ ] Rendered verification occurs when the environment supports it

A hard-gate failure means the UI is not ready.

# <img src="./assets/icons/check-circle.svg" width="28" align="center" alt="" /> Millie Standard

Before considering a significant interface complete:

- [ ] Does the interface clearly belong to this product?
- [ ] Is the primary user job obvious?
- [ ] Is information architecture understandable?
- [ ] Is the visual direction intentional?
- [ ] Is typography product-appropriate?
- [ ] Is the palette semantic and accessible?
- [ ] Are spacing and proportion controlled?
- [ ] Does the interface adapt to available space?
- [ ] Is mobile intentionally recomposed?
- [ ] Are native platform conventions respected?
- [ ] Are all reachable interaction states designed?
- [ ] Is keyboard/touch/pointer behavior appropriate?
- [ ] Is motion purposeful?
- [ ] Is reduced-motion behavior available?
- [ ] Are scroll effects justified?
- [ ] Is the selected motion engine appropriate?
- [ ] Is 3D justified?
- [ ] Does 3D have a performance/fallback strategy?
- [ ] Is the component ecosystem coherent?
- [ ] Were external components checked for fit and provenance?
- [ ] Are loading/empty/error states complete?
- [ ] Does long/localized content survive?
- [ ] Are performance costs understood?
- [ ] Does the design avoid obvious AI-template combinations?
- [ ] Does it differ meaningfully from unrelated recent projects?
- [ ] Was the actual rendered experience inspected when possible?
- [ ] Could a capable design/engineering team plausibly ship it?
